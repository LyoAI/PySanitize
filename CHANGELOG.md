# Changelog

## [Unreleased]

middle.json is the primary parse source with per-line geometry, PDF inputs gain a layout-preserving `redacted.pdf`, xlsx and json sources redact **in place** (native producers, MinerU bypassed, no markdown), image masking becomes field-driven, and masking can optionally become reversible (`--recoverable` / `--recover`) with offset-exact restoration for structured artifacts.

### Added

- **Resumable batch runs** (`scripts/batch_sanitize.py`): an interrupted batch — Ctrl-C, crash, reboot — is continued by rerunning the same command; completed files are skipped and the file in flight (which never got its audit) is redone. A job counts as done only when its `audit.json` parses **and** every artifact the audit names actually exists (a deleted/truncated `redacted.json` or a half-written audit from a killed run is redone, never silently skipped); the startup line reports `resuming: N already sanitized, M to do`, `--resume` states the default explicitly (mutually exclusive with `--force`, which redoes everything). `batch_summary.json` is rewritten after every file and carries a `status` (`running` / `interrupted` / `complete`), so an aborted run leaves a usable record instead of nothing; Ctrl-C writes the summary, prints what remains, and exits 130. Each file's result is released and collected before the next one starts, so one large file's peak does not stack on the next file's
- **Excel in-place redaction** (`pysanitize/redact/xlsx.py`): xlsx sources yield `redacted.xlsx` with sensitive cells replaced **at the source** (a spreadsheet has no overlay to draw) — always on, and **no `sanitized.md` is produced** (the redacted workbook is the output); hidden/veryHidden sheets included. xlsx parsing switches to a **native openpyxl producer** (`pysanitize/parser/xlsx.py`, MinerU bypassed — it adds no geometry and reformats displayed values): every cell carries `(sheet, row, col)` provenance in the document text (`Block.cells` / `CellBox`, the spreadsheet analog of `LineBox`), so detection runs on exactly the strings written back and the offset→cell mapping is exact by construction. Numbers/dates render as displayed (`13800138000`, `2024-03-01` — never `.0` or a phantom midnight, per the cell's number format); a formula without a cached value renders its literal text so embedded literals stay detectable. Beyond edited cells: docProps always scrubbed, comments / sheet names / formula literals *echoing a detected value* scrubbed (sheet renames stay Excel-legal — `*` is forbidden in titles), chart series caches (strCache/numCache) dropped, `fullCalcOnLoad` set. `verify_redaction_xlsx` is byte-level — every text zip member searched for every value, `html.unescape`d first because openpyxl writes non-ASCII strings as `&#NNNNN;` references a raw grep silently misses; leftovers land in `redaction_leftovers` (member names) exactly like the PDF path. `openpyxl` promoted to a runtime dependency (xlsx *parsing* needs it, not just redaction; the `render-office` extra keeps `python-docx` for the future DOCX renderer). Known P2 edges, documented in the README: comments are not independently detected (only value-echo scrubbed), embedded images pass through with a warning, pivot-cache leftovers are reported by verification
- **JSON in-place redaction** (`pysanitize/parser/json.py`, `pysanitize/redact/json.py`): json sources yield `redacted.json` — always on, **no `sanitized.md`, MinerU never invoked** (only PDF/DOCX-type documents go through MinerU). A native producer walks the parsed tree; every string leaf becomes one line of detection surface carrying its traversal path (`JsonBox.path` → `$.员工[0].备注`), so detection runs on exactly the values written back — the same by-construction guarantee as xlsx. Top-level arrays paginate per element (an empty element emits no block but never shifts numbering — the xlsx empty-sheet lesson); scalars render xlsx-style (integral float `5.0` → `5`, bool `true`/`false`; newlines flatten to spaces *for detection only* — a length-preserving substitution, so rewritten leaves keep theirs). The writer replaces leaf values only: key order, nesting, untouched leaves and indentation follow the source (`_source_style` sniffs indent/newline — minified in, minified out); keys are schema, not data — a value echoed in a key is *reported* by verification, never rewritten. Number/bool leaves mask to strings (JSON has no masked number); `verify_redaction_json` is data-level (re-load, walk string leaves + rendered numbers/bools + keys, report survivors with their json paths — complete, since JSON carries no off-surface metadata). Regions count leaves, not spans (one leaf with two phones is one region)
- **Offset-exact recovery for structured artifacts**: `--recoverable` now records, per span, where the masked value sits **inside** the rewritten cell/leaf — `cells` / `json` entries gain `masked_start`/`masked_end`, computed arithmetically in resolve (sorted replacements, accumulated length delta — pure arithmetic shared by redact and recover, never a search). `--recover redacted.xlsx|redacted.json` validates each recorded slice (`text[ms:me] == masked_value`) and splices highest-position-first, all-or-nothing per cell/leaf — so several look-alike placeholders in one string (two masked names both `***`, or a literal `***` planted in the text) can never cross-restore; a placeholder no longer at its position counts as unresolved, never mis-spliced. Whole-cell/leaf numbers, dates and bools restore **with their original python type** (via the recorded kind tag); legacy audits without offsets still recover by string matching as before
- **Recoverable masking** (`pysanitize/recover/`, new `recover` extra): `--recoverable` keeps the document's normal placeholders — the sanitized output is indistinguishable from a plain run — while `audit.json` additionally records each value's AES-GCM ciphertext (`encrypted_value`, key derived from a passphrase via scrypt; same value → same ciphertext per run) plus its position: `start`/`end` original offsets, `md` placeholder range in sanitized.md, `rects` redacted PDF rectangles (xlsx runs: `cells` coordinates + type tags). A public `recovery` block records algorithm / KDF / salt / params — never key material. `pysanitize --recover <sanitized.md|redacted.pdf|redacted.xlsx|redacted.json>` restores the originals: markdown exactly (splice at the recorded range, verified against the placeholder), PDF best-effort (rects cleared, decrypted value re-inserted; images are not recoverable), xlsx per-cell and json per-leaf exactly, by recorded position and with types. Passphrase resolution: `--recover-key` > `$PYSANITIZE_RECOVER_KEY` > `.recover.key` (0600, generated beside audit.json when absent); whichever way the key is supplied, the **effective key is always materialized into `.recover.key`** so restoration simply reads that file — recovery itself never generates or rewrites a key. TUI gains a **Recoverable** switch + password-masked recovery-key input on ② Options, and a new **⑥ Recover** tab (pick the sanitized document, optional audit path + passphrase) so restore runs inside the TUI too
- **PDF redaction** (`pysanitize/redact/`): opt-in for PDF sources (`--redact-pdf` / `output.redact_pdf`) — the pipeline writes `redacted.pdf` beside `sanitized.md` with sensitive spans truly *deleted* from the content stream (`apply_redactions(text=0)`) and replaced with a mosaic (or solid box, `--redaction-style block`); table borders and vector graphics survive (`graphics=0`); overlapping image pixels are cleared (`images=2`). `verify_redaction()` re-reads the output and reports leftovers loudly: deduped `(value, page)` pairs, logged at error level (was a warning + count) — `audit.json` gains raw-free `leftover_count`/`leftover_pages`, the values land in `sensitive_report.json` (`redaction_leftovers`), and the CLI prints a warning line when any survive. `SanitizeResult.redacted_pdf` + audit `redaction` stats
- **Field-driven image masking** (`image.fields` / `--image-text <field-list>`): each extracted image is OCR'd (PaddleOCR) and the **same text field detectors** run over the recognized text; only the matching spans are mosaiced. Default (`null`) follows the text field set; an explicit list may be a superset; `[]` disables it. Near-full-page scan images are skipped (their text is already handled as document text). Complementary to the existing class-driven detectors
- **`pysanitize/parser/middle.py`**: MinerU `middle.json` projection — per-line geometry projected into `Block.line_boxes` (`LineBox`), TOC (`index`) dropped from text but kept as empty placeholders so per-page order aligns with v2 records, image/chart blocks carry `image_path` + `image_bbox`, and table markdown is recovered from v2 `html` (geometric bbox match, ±1 positional retry fallback, caption-only fallback). Page sizes surface as `ParsedDocument.page_dimensions`
- **TUI ③ Image tab**: image masking targets (enable switch, class list, all-text switch, detector) plus a "Same as text" toggle and a field `SelectionList` for image-specific fields; tabs renumbered to display order (① Fields ② Options ③ Image ④ Run ⑤ Results); `shape_params` keeps explicit empty lists (`image_fields=[]`) so "no field-driven masking" survives
- **`pymupdf` promoted to a runtime dependency** (was dev-only) — the only dependency that both reads and faithfully rewrites a PDF; AGPL-licensed, documented in the README

### Changed

- **Breaking: structured sources redact in place, out of the box** — `--redact-xlsx` / `output.redact_xlsx` are removed (no replacement needed: xlsx — and the new json — sources *always* produce their redacted artifact), and xlsx/json runs **no longer produce `sanitized.md`** (`SanitizeResult.sanitized_md` is `None` for them; the CLI drops the md line and prints the redacted artifact paths instead). Only PDF/DOCX-type documents go through MinerU
- **The internal-only provider is gone** (its module, extra and tests were removed for open-sourcing). The provider/model mechanism is unchanged — every provider section in a model yaml is an OpenAI-compatible endpoint, so `--provider` accepts `openai` / `claude` / `openrouter` / any section name
- **`.recover.key` is the single source of truth for `--recover`**: every `--recoverable` run now materializes the *effective* passphrase into `.recover.key` (0600) — whether it came from `--recover-key`, `$PYSANITIZE_RECOVER_KEY` or an auto-generated draw (previously only the auto-generated key was written). Restoration therefore just reads that file, with no need to recall how the key was supplied; the CLI/TUI flags and env var remain as overrides, and recovery still never invents or rewrites a key
- **Parse source is `middle.json`**, not `content_list_v2` — every span carries page coordinates, so detections map onto page rectangles (`resolve_rects` → in-line proportional sub-boxes / whole-block bbox for tables) instead of a coordinate-less derived projection. v2 remains for table cell text and as a fallback when a backend emits no `pdf_info`
- **CLI**: image flags follow the model boundary — `--image-classes face,person` (detection models) + `--image-text [fields]` (OCR: bare = all printed text, field list = only matching fields), replacing `--image-classes` / `--image-fields`; boolean switches are uniform store_true opt-ins — `--mask-images`, `--audit`, `--redact-pdf` (replacing `--no-redact-pdf`) mean "on" by presence, absent always means "config decides"); `--parse-backend` renamed `--mineru-backend`; `_run_sanitize` prints the `redacted.pdf` path
- **`config/pipeline.yaml`**: `output.redact_pdf` (default false — redaction is opt-in) + `output.redaction_style` (mosaic) + `output.recoverable` (default false — reversible masking is opt-in), `image.fields` (null = follow the text fields)
- **`<file>` promoted to the top-level CLI command**: `pysanitize sample.pdf --detector hybrid`; the pre-0.3 `pysanitize sanitize sample.pdf` form keeps working as an alias; `--launch tui|webui` selects an interactive frontend
- **All pipeline tunables centralized in `config/pipeline.yaml`** (`text.chunking.*`, `text.min/max_value_len`, `text.max_completion_tokens`, `image.mosaic_factor`, `image.haar/ocr/yolo.*`, …); Python modules keep only sentinel defaults resolved from config at call time — no scattered module-level constants
- Removed the dead `utils/skill_loader.py`
- **MinerU parse cache keyed by source folder**: the default parse root is `.cache/<source folder name>/` (was `.cache/md/<stem>/`), so same-named files in different folders never share a parse cache; explicit override via the new `--mineru-out-dir` flag (and a TUI ② Options field)

### Removed

- **Post-redaction verification is gone from the pipeline** (PDF, xlsx and json alike) — the run now ends at redact + report, dropping the step that re-read the output hunting for surviving values (405 s of a 416 s 90 MB-json run, and the source of the recurring "N sensitive values still present" errors, which in practice reported the rules detector's own false positives back at the operator). Removed with it: `SanitizeResult.redaction_leftovers`, the audit `redaction.leftover_count`/`leftover_pages` keys, the `sensitive_report.json` `redaction_leftovers` list, the CLI's ⚠ leftover line, and the batch summary's `leftovers` field. `verify_redaction` / `verify_redaction_xlsx` / `verify_redaction_json` remain in `pysanitize.redact` as **manual audit tools** (their unit tests stay): hand them a redacted artifact plus the values from `sensitive_report.json` for a spot check. Consequence to own: a value the detector missed in one context but caught elsewhere is no longer reported — the audit's raw values are the only trail

### Fixed

- **Rewritten JSON leaves and xlsx cells lost their embedded newlines** (visible only after `--recover`: the restored text came back one line): detection needs one leaf/cell per line, so the parser flattens `\r`/`\n` to spaces on the surface — but the redactors spliced and wrote back that flattened copy, so *every* newline in an edited leaf/cell disappeared, including in text no mask touched (untouched leaves were fine). The flattening is a 1:1 replacement, so the same offsets index the raw value: both redactors now splice over the source string when its flattened form equals `edit.text` (json leaf / xlsx cell value), and fall back to the rendered text for numbers, formulas and rich text. Redacted output keeps its line breaks and recovery restores the original **byte-identically** (verified with `\n` and `\r\n` in multi-line leaves: 0 unresolved, deep-equal). Artifacts that were **already** sanitized by a pre-fix build can be repaired without re-sanitizing: `--recover` gains `--restore-newlines-from <original.json|original.xlsx>`, which compares each restored leaf/cell with the source's flattened form and — where they match exactly — takes the source text, putting back the line breaks the old redactor consumed (an unresolved placeholder or a leaf edited after sanitizing never matches, so nothing is guessed). `scripts/batch_recover.py` gains the matching `--source-root <folder that was sanitized>`: the batch layout mirrors the input, so each `redacted.json` / `redacted.xlsx` picks up its own source (disambiguated job dirs like `report-json/` included) and the restored batch is byte-identical again
- **Peak memory on large structured files dropped by a third to over half** (the "memory keeps climbing" batch observation): nothing was leaking — `gc.get_objects()` and `sys.getallocatedblocks()` are flat across repeated runs (the creep is CPython keeping freed arenas resident, so RSS settles near the batch's largest file) — but that peak was far higher than the work required. A 99 MB / 360k-span json held the source text, the parsed tree, the serialized output **and** its utf-8 bytes simultaneously: `redact_json` now streams (`json.load`/`json.dump`, indent sniffed from the file head plus its last byte instead of a 99 MB string), `write_audit` / `write_sensitive_report` stream their serialization (a 149 MB audit was built as a string, then encoded as a second full copy), and the pipeline drops the per-leaf/per-cell provenance tables (`JsonBox` / `CellBox` — one per leaf, 360k of them) immediately after the artifacts are written, before the audit's per-span dicts stack on top. Measured peak RSS on a 99 MB json: 1503 MB → 986 MB plain, 2450 MB → 1137 MB with `--recoverable`; outputs byte-identical, recovery still byte-identical with 0 unresolved
- **Redaction still hung on checklist-style JSON** (right after `resolved N leaf(s)`, the stage that logs nothing): masked values were assembled with one whole-string copy per replacement (`text = text[:s] + rep + text[e:]`), costing *replacement count × leaf length*. Fine for short leaves, ruinous for the real shape — a 72 MB export whose ~400 leaves are giant text blobs with ~90k hits between them, where a single 740k-char leaf with 35k hits took 3.9 s and scales with the product (tens of minutes to hours at scale). All four splice sites (json redact, xlsx redact, json/xlsx recover, markdown recover) now share `pysanitize/utils/splice.py::apply_repls` — one ascending pass and a join, O(len + n) — byte-identical to the old output, including duplicate same-range repls (an ID card that also matches the bank-card rule: last recorded wins, as before). 99 MB / 360k-span fixture: redact 3.2 s → 0.34 s (740k-char single-leaf worst case: 3.9 s → 0.0045 s), e2e 16 s with byte-identical restore of all 360k values
- **Top-level-array JSON failed to redact** (`FAILED [in-place] list indices must be integers or slices, not str` on every such export): the parser paginates a top-level array one block per element but built each element's leaf paths from an *empty* root, while `redact_json`, audit and recovery all walk paths from the real root — a list. Element 0's phone recorded as `("手机号",)` therefore indexed the root list with a string (the TypeError), bare-row arrays raised `tuple index out of range`, and nested arrays did not raise at all: index `(0,)` is a legal list index, so redaction silently **replaced the inner row** with the masked string. Element paths now start at their own 0-based index; all three shapes round-trip deep-equal, and the 90 MB top-level-array fixture recovers byte-identically (24.7 s sanitize, 4.1 s recover, 0 unresolved)
- **Company detection hung on company-name-dense documents** (the batch hang the KeyboardInterrupt traceback finally pinned): `_detect_companies` checked every candidate against every already-accepted span (`any(s <= start and end <= e for s, e in covered)`) — and a 案例-style workbook is wall-to-wall company names, so candidates and accepted spans grew together, quadratically. Accepted spans form a staircase (candidates arrive by ascending start, longest first; contained ones are skipped — so starts *and* ends strictly increase), which lets containment be decided by bisecting to the floor start alone: its end is the largest among spans that could contain the candidate. 16k-row company-dense xlsx (64k detections): detect 142 s → 13.4 s; outputs verified identical (3000 randomized candidate sets, old vs new)
- **Pipeline stage progress is logged** (`parsed … chars` / `detected … spans` / `resolved …` / `audit written`), and `batch_sanitize` prints a `processing (N MB)` line the moment each file starts — a multi-minute stage between two success lines looked exactly like a hang
- **Large documents are no longer quadratic** (the batch one-file-for-an-hour bug): three hot spots dominated big files. A top-level-object JSON parses to ONE block holding every leaf, and a sheet to ONE block holding every cell — so `resolve_cells`/`resolve_json_values` walked every box/cell per detection, and the candidate slice copied the giant list each time; `verify` checked every value against every leaf / zip member; the comment/formula scrub multiplied formulas by values. Fixes: resolve candidates are now a bisect-bounded **index range** (zero copy); the scrub and both verifies use a shared n-gram prefilter (`pysanitize/redact/_grams.py` — 4-grams for ≥5-char values, 2-grams for short CJK ones; digit values share 2-grams like `13`, so 4-gram digit buckets stay tiny), with xlsx verify matching `\w+` tokens per member (exact for word-only values — they can only sit inside one maximal word run) and falling back to the direct blob grep for values with non-word characters. Measured on a 2.9 MB JSON (3k customers, 30k detections) and a 10k-row workbook (63k detections): json resolve 320 s → 0.10 s, json verify 131 s → 0.67 s (e2e 7.5 min → 2.3 s), xlsx resolve 9.4 s → 0.32 s, xlsx verify 79 s → 8.7 s (20k-row recoverable e2e 138 s → 14.7 s). Behavior identical — full suite green, leftover counts unchanged
- **verify stayed quadratic on text-heavy documents**: the prefilter above collected per-text candidates from gram buckets, but real value sets collide on prefix grams — ID cards sharing a region code put 7.5k values into one 4-gram bucket, and every text position hitting it ran thousands of full-text substring searches (90 MB / 427k-detection json: verify 405 s of a 416 s run). `_grams.py` now indexes each value by its globally **rarest** gram and verifies positionally (`ValueMatcher`): a gram hit is confirmed with one slice compare at the only offset the value could start at — no candidate expansion, and no false negatives (a value present in the text necessarily has its rarest gram present). Same 90 MB run: verify 405 s → 14.7 s (all stages 416 s → 25 s), recoverable CLI e2e 31 s, recover 4.3 s for 427k values with 0 unresolved; behavior identical (same leftover counts) and a regression test pins exactness under shared prefixes
- **`--fields` now actually re-enables disabled-by-default fields**: `RuleDetector` re-applied the *enabled* filter to the pipeline's pre-selected specs, so explicitly naming a disabled field (e.g. `--fields bank_account`) was silently a no-op — the field appeared in audit `fields` but never produced a detection. The pipeline now passes `fields` through to the detector (same as the OCR rule detector always did)
- **Short values are never emitted unmasked**: `MaskSpec.mask` could return a value verbatim when `keep_head + keep_tail` covered the whole string — e.g. a 7-digit hotline `9555526` with the phone mask (keep 3+4) passed through unchanged in `sanitized.md`. Now the head is kept and the remainder is masked (`955****`), with at least one character always hidden
- **Partial overlaps merge instead of corrupting**: `resolve()` only dropped *contained* spans, so two partially overlapping detections both reached the masker, whose absorbed branch silently *deleted* the uncovered tail (never masked, the characters vanished from `sanitized.md` and could never be recovered). Overlaps now merge into their union in `resolve()` — verbatim union text, every character masked exactly once — and the masker masks any residual uncovered tail instead of dropping it
- **Merged unions never publish the other field's content**: a union span that kept a `keep_head`/`keep_tail` mask exposed characters from the *other* field (person `张三` inside a phone overlap surfaced as `张三1******…`). A grown union now takes the highest-priority identity whose mask reveals nothing (a fixed template); containment keeps the outer field's identity untouched
- **Type priority actually holds**: `_score()`'s type term ranked fuzzy `person_name` above exact fields — the inverse of `_TYPE_ORDER`'s documented priority. Invisible before (containment never consulted the score across types), decisive now that overlaps merge; the rank mapping is inverted so a higher score means a more exact field
- **PDF recovery no longer truncates long values**: `_insert_fitted` sized text by `width × 1.55 / len`, but CJK glyphs are ~1.0em wide — a long value on a wide (whole-block table) rect ran past the page edge and its tail glyphs were clipped (`一政策性银行` came back as `一政策性银`). The size now follows a per-character width estimate (CJK 1.0em / ASCII 0.55em, 0.96 margin); verified on the full 北京银行 annual report — recovered-PDF text search went from 47/617 unique values missing to 0
- **`.env`-only passphrases now reach `--recover`**: the recover package is deliberately independent of the pipeline, so `pysanitize --recover` never imported `pysanitize.config` and a `PYSANITIZE_RECOVER_KEY` set only in the repo-root `.env` was silently ignored on the recover path (the sanitize path loaded it via config). The env var is also renamed `PY_SANITIZE_RECOVER_KEY` → `PYSANITIZE_RECOVER_KEY` (matching the `pysanitize` name); the recover package now loads the repo-root `.env` directly (shell-exported vars still win), so all three passphrase sources work for both directions

- **Table recovery survives index drift**: table markdown was recovered by positional ±1 alignment onto v2, so a block dropped/added between the two projections drifted every later table on the page to the caption-only fallback. Alignment now matches per-page geometry first (the v2 bbox is the same para block normalized to 0..1000), with the positional retry kept for bbox-less records
- **Redaction leftovers are visible and deduped**: `verify_redaction` returned an unduped value list and the pipeline logged only a count at warning level — a value detected N times and still present counted N times, and the operator couldn't see which values/pages survived. It now returns deduped `(value, page)` pairs, logs at error level with the affected pages, and records the values in `sensitive_report.json` with raw-free counts in `audit.json`
- **PDF recovery no longer fills the page with giant overlapping glyphs**: `_insert_fitted` sized the font off the redaction rect — a whole-table block bbox is tall and wide, so a short value came back at ~70–100pt, and every masked cell in a table (all resolving to that same bbox) was written at the same anchor, stacking on top of each other. The font now follows the page's body text (median of spans near the rect, page-median fallback), and values that share a rect are stacked top-down in reading order
- **CI installs the `recover` extra**: GitHub Actions synced only `--extra tui`, so `cryptography` — the recover extra's AES-GCM backend — was missing and the whole `test_recover.py` suite failed on the runners with `RuntimeError: recoverable masking needs the 'recover' extra`. The workflow now installs `uv sync --frozen --extra tui --extra recover`
- **Field-driven image masking boxes align on later OCR lines**: `OCRFieldDetector` joined the OCR'd line texts *without* the `"\n"` separator its line-box offsets accounted for, so every line after the first drifted one char per preceding line — mosaic boxes sat left of their text, a value's trailing characters escaped the mosaic, and a short hit far enough into a late line was dropped entirely (unmasked leak). The join now includes the separator, matching the document-text path; a regression test pins a hit on line 3 of 3 to full digit coverage

## [0.2.0] - 2026-08-24

Image desensitization generalized from "faces only" to **class-driven**: the user
names the targets, the detection model locates them, and they get mosaiced.

### Added

- **detector/image**: `FaceBox` → `DetectedObject` (new `label`: `face` / `text` / a YOLO class name; `FaceBox` kept as an alias)
- **YOLO class filtering**: `YOLODetector(classes=[...])` supports arbitrary weights + per-class filtering (`row.cls` → `model.names`); `YOLOFaceDetector` alias kept
- **OCR text regions**: `OCRTextDetector` (PaddleOCR, `--extra image-ocr`); the `text` class mosaics every printed-text region in an image (company names / seals / screenshots)
- **`build_detectors(classes, ...)`**: class → backend routing — `face` → YuNet/Haar/YOLO, `text` → OCR, anything else → YOLO class filter; missing backends degrade with a warning instead of crashing
- **No image detection by default**: with `image.classes` empty, `--mask-images` leaves images untouched (better to miss than to wrongly mosaic); CLI gains `--image-classes face,text,person` (comma-separated)

### Changed

- **LLM provider/model selectable**: CLI adds `--provider` (a provider section in `config/llm/<model>.yaml` — e.g. `openai`/`claude`/`openrouter`) and `--model`, matching finsearch-bench; `sanitize_document(llm_provider=...)` + `config/pipeline.yaml` `text.provider`
- `config/pipeline.yaml` gains `image.classes` (default `[]`); `image.detector` is now the "face backend" setting
